# هم‌آوا — HamAva 1.0.4

وب‌اپ شخصی ترجمه و دوبله فارسی با رابط راست‌به‌چپ، پلیر داخلی و کلید Gemini متعلق به خود کاربر. نسخه موبایل، انتخاب حالت و دکمه «شروع ترجمه» را همیشه پایین صفحه در دسترس نگه می‌دارد.

## اجرای مستقل از Sites و آماده برای GitHub

پیش‌نیاز: Node.js نسخه 22.13 یا بالاتر و pnpm نسخه 11.25.0. کد رابط و ترجمه با Next.js معمولی هم اجرا می‌شود و به حساب Sites، پایگاه داده یا کلید داخل سورس نیاز ندارد.

```bash
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev:standalone
```

سپس `http://localhost:3000` را باز کن. کلید را در تنظیمات خود وب‌اپ وارد کن؛ کلید را داخل کد، README یا GitHub قرار نده.

برای خروجی نهایی و اجرای آن:

```bash
pnpm build:standalone
pnpm start:standalone
```

برای بررسی کد:

```bash
pnpm test
pnpm typecheck
```

### انتقال به GitHub

فایل ZIP سورس را باز کن و محتوای پوشه `HamAva` را در مخزن خودت قرار بده. `pnpm-lock.yaml`، پوشه `public` و فایل‌های نقطه‌دار مثل `.gitignore` را هم نگه دار. فایل‌های محیطی، پوشه `node_modules` و خروجی‌های ساخت در `.gitignore` هستند. بسته سورس با `git archive` ساخته می‌شود؛ `.gitattributes` شناسه شخصی میزبانی Sites را از آن حذف می‌کند.

```bash
git init
git add .
git commit -m "Add HamAva Persian video translator"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

نام کاربری و نام مخزن خودت را در آدرس بالا جایگزین کن. برای استفاده روی گوشی، پروژه را روی میزبان سازگار با Next.js و HTTPS منتشر کن. صرفاً آپلود کد به GitHub، وب‌اپ را آنلاین نمی‌کند؛ برای اینکه صفحه واقعاً باز شود، بخش «انتشار روی GitHub Pages» پایین را دنبال کن.

اسکریپت‌های `dev`، `build` و `start` برای انتشار موجود با Sites/Vinext حفظ شده‌اند. برای اجرای عادی، فرمان‌های `:standalone` بالا را استفاده کن. در نسخه مستقل، ورود اختصاصی Sites وجود ندارد؛ اگر وب‌اپ را خصوصی می‌خواهی، دسترسی را در میزبان خودت تنظیم کن.

## انتشار روی GitHub Pages

وب‌اپ کامل در مرورگر اجرا می‌شود و به سرور خودش نیازی ندارد؛ پس می‌توان آن را کاملاً ایستا روی GitHub Pages منتشر کرد. ساخت ایستا را `pnpm build:pages` انجام می‌دهد و نتیجه در پوشه `out/` می‌افتد. این اسکریپت `next build` را با `output: "export"` اجرا می‌کند و به مسیر ساخت Sites/Vinext دست نمی‌زند.

```bash
pnpm install --frozen-lockfile
pnpm build:pages
```

سپس در مخزن، **Settings ← Pages ← Build and deployment ← Source** را روی **GitHub Actions** بگذار و شاخه `main` را push کن (یا workflow را دستی اجرا کن). فایل `.github/workflows/pages.yml` اول `pnpm test` را اجرا می‌کند، بعد خروجی ایستا را می‌سازد و همان را منتشر می‌کند.

هر دو حالت آدرس‌دهی خودکار پشتیبانی می‌شوند:

| حالت | نشانی نهایی | مسیر پایه |
| --- | --- | --- |
| مخزن `<user>.github.io` یا دامنه اختصاصی | `https://<user>.github.io/` | خالی |
| مخزن پروژه‌ای مثل `HamAva` | `https://<user>.github.io/HamAva/` | `/HamAva` |

workflow نام مخزن را می‌خواند و مسیر پایه را خودش تعیین می‌کند. برای ساخت دستی روی زیرمسیر:

```powershell
$env:HAMAVA_BASE_PATH='/HamAva'; pnpm build:pages   # PowerShell
```

```bash
HAMAVA_BASE_PATH=/HamAva pnpm build:pages           # Linux و macOS
```

زیرمسیر فقط روی فایل‌های `public/` اثر می‌گذارد و هر سه مورد حل شده است: مسیر worklet صدا و service worker در زمان اجرا از خود صفحه محاسبه می‌شود (`lib/hamava/assets.ts`)، مسیر فونت‌ها با پلاگین PostCSS در `postcss.config.mjs` پیشوند می‌گیرد، و `manifest.webmanifest` و آیکن‌ها مسیر نسبی دارند. وقتی `HAMAVA_BASE_PATH` تعیین نشده باشد هیچ پیشوندی اعمال نمی‌شود و رفتار فعلی میزبان ریشه عوض نمی‌شود.

نکته‌های میزبانی Pages:

- Pages روی HTTPS است؛ پس میکروفون، `AudioContext`، ضبط WebM و افزودن به صفحه اصلی گوشی همه کار می‌کنند.
- کلید Gemini در مرورگر کاربر می‌ماند؛ در مخزن، در خروجی `out/` و در workflow هیچ کلیدی وجود ندارد. برای خصوصی‌بودن صفحه، مخزن باید خصوصی باشد و Pages برای مخزن خصوصی به پلن پرداختی نیاز دارد.
- سهمیه Pages برای استفاده شخصی کافی است: حدود ۱۰۰ گیگابایت پهنای‌باند در ماه و ۱۰ ساخت در ساعت.
- دسترسی مرورگر به `generativelanguage.googleapis.com` و `youtube.com` باید آزاد باشد؛ Pages واسطه‌ی این ارتباط نیست و ترجمه روی سرور GitHub انجام نمی‌شود.
- Pages هدر پاسخ دلخواه نمی‌پذیرد؛ سیاست‌های امنیتی مثل CSP را فقط می‌توان با متا در صفحه اضافه کرد.
- برای بازبینی خروجی روی رایانه، `out/` را با یک سرور ایستا سرو کن (`npx serve out`). اگر با `HAMAVA_BASE_PATH` ساخته‌ای، همان زیرمسیر را محلی هم شبیهسازی کن.

## امکانات و مسیر کار

- **فایل یا لینک مستقیم:** تحلیل دسته‌ای با مُهر زمانی از خود رسانه و تنظیم خودکار روی گفتار واقعی؛ فایل‌های بسیار بزرگ با ترجمه زنده اجرا می‌شوند. لینک مستقیم باید HTTPS، قابل پخش و دارای مجوز CORS باشد.
- **یوتیوب عمومی:** لینک عمومی مستقیماً برای یک تحلیل کامل به Gemini فرستاده می‌شود؛ صدای iframe استخراج نمی‌شود. برای کمترین تأخیر، فایل یا لینک مستقیم را وارد کن.
- زیرنویس، دوبله یا هر دو؛ صدای اصلی ۰–۱۰۰٪ و دوبله ۰–۱۵۰٪؛ کاهش صدای اصلی هنگام دوبله.
- انتخاب خودکار صدای آماده زن/مرد برای یوتیوب یا انتخاب دستی Kore/Charon؛ تنظیم سرعت گفتار برای هماهنگی زمانی.
- اندازه، رنگ، جای زیرنویس، پس‌زمینه، متن دوزبانه، تأخیر زمانی و خروجی SRT.
- زیرنویس‌های بلند به جمله‌های کوتاه و بازه‌های زمانی جدا تقسیم می‌شوند تا فقط cue فعال روی تصویر بماند.
- برای فایل و لینک مستقیم، خروجی ویدیوی دوبله‌شده‌ی WebM با ترکیب صدای اصلی و دوبله در خود مرورگر ضبط می‌شود؛ ضبط باید یک‌بار در زمان واقعی انجام شود. برای همه منابع (از جمله یوتیوب) فایل WAV صدای دوبله به‌صورت آفلاین ساخته می‌شود.
- ذخیره اختیاری کلید و تنظیمات در همان مرورگر و افزودن به صفحه اصلی گوشی.

## کلید و داده‌ها

کلید مستقیماً از مرورگر به Google فرستاده می‌شود. سرور هم‌آوا کلید را دریافت یا نگه‌داری نمی‌کند. ذخیره اختیاری در `localStorage` رمزنگاری جداگانه ندارد؛ می‌توان ذخیره را خاموش یا کلید را حذف کرد. هیچ کلید واقعی، توکن انتشار یا فایل محیطی در بسته سورس قرار ندارد.

آخرین ترجمه و کلیپ‌های دوبله در IndexedDB همین مرورگر ذخیره می‌شوند؛ برای بازیابی، همان فایل (نام، اندازه و تاریخ تغییر یکسان) یا همان لینک را دوباره انتخاب کن. فایل اصلی و کلید در این آرشیو ذخیره نمی‌شوند. آخرین خروجی ویدیو و آخرین بخش صدای زنده نیز پس از پایان ضبط نگهداری می‌شوند. پاک‌کردن داده‌های سایت، حالت خصوصی یا محدودیت فضای مرورگر می‌تواند این آرشیو را از بین ببرد؛ برای نگهداری مستقل، خروجی را دانلود کن. حذف آرشیو از تنظیمات ممکن است.

## انتشار ۱.۰.۴ — سازگاری با کلید جدید Gemini

گوگل کلیدهای جدید AI Studio را از نوع Authorization و با قالب‌هایی مانند `AQ.` می‌سازد. اعتبارسنجی وب‌اپ دیگر پیشوند `AIza`، طول ثابت یا کاراکترهای محدود را فرض نمی‌کند؛ کلید به شکل متن امن چاپ‌پذیر در هدر `x-goog-api-key` برای APIهای HTTPS ارسال می‌شود. اتصال زندهٔ WebSocket از همان کلید در نشانی اتصال استفاده می‌کند، چون مرورگر اجازه تنظیم هدرهای دلخواه WebSocket را نمی‌دهد. خطاهای نمایشی کلید را می‌پوشانند. کلیدهای Standard قدیمی ممکن است به‌علت سیاست گوگل پذیرفته نشوند؛ در AI Studio کلید جدید Authorization بساز و جایگزین کن.

## انتشار ۱.۰.۳ وب‌اپ

شماره نسخه بنا به تصمیم صاحب پروژه از ۱.۵.۰ به ۱.۰.۳ تغییر کرده است. این مخزن همچنان وب‌اپ است؛ بسته افزونه مرورگر پروژه جداگانه‌ای است.

- زیرنویس آماده فایل محلی و لینک مستقیم اکنون هنگام پخش و جابه‌جایی زمان دیده می‌شود.
- حالت فقط زیرنویس، صدای اصلی را با حجم کامل پخش می‌کند.
- انتخاب صدای زن/مرد برای همه منابع آماده‌سازی در دسترس است؛ این قابلیت کپی هویت صوتی گوینده نیست.
- خروجی ویدیو از دوبله آماده ساخته می‌شود و جلسه API تازه‌ای راه نمی‌اندازد. ترکیب خروجی مستقل از ولوم شنیدن است: دوبله کامل و صدای اصلی ۲۵٪، با کاهش اختیاری هنگام صحبت.
- WAV جمله‌های بلند را به‌جای قطع‌کردن، با هم‌پوشانی موج در بازه زمانی جا می‌دهد؛ حفظ زیر و بمی تقریبی است و تغییر شدید مدت می‌تواند کیفیت را کاهش دهد. خطای خواندن کلیپ دیگر به‌صورت فایل ناقصِ ظاهراً موفق پنهان نمی‌شود.
- خروجی SRT و VTT شامل مرتب‌سازی، حذف زمان نامعتبر، جایگزینی تکرار هم‌زمان و رفع هم‌پوشانی است.
- ترجمه و صدای آماده و آخرین خروجی‌ها در مرورگر قابل بازیابی‌اند.
- دوبله زنده، در مرورگر دارای MediaRecorder، پس از توقف هر بخش با قالب WebM/Opus (یا M4A در مرورگر سازگار) قابل دانلود است. این فایل صدای همان بخش پخش‌شده است، نه بازسازی کامل خط زمانی اصلی؛ مکث یا جابه‌جایی زمان بخش تازه‌ای می‌سازد و فقط آخرین بخش نگهداری می‌شود.
- قطع اتصال یا فشار شبکه پخش زنده را متوقف می‌کند تا صدا در سکوت دور ریخته نشود. در پایان طبیعی فایل، تا ۸ ثانیه برای پاسخ نهایی و پایان صف صوتی فرصت داده می‌شود.

محدودیت‌های خروجی: ضبط ویدیو به `captureStream` و `MediaRecorder` نیاز دارد؛ در مرورگر فاقد این قابلیت‌ها، WAV و زیرنویس را جدا دریافت کن. ضبط ویدیو/صدای زنده در ۶۴ مگابایت متوقف می‌شود و بخش ضبط‌شده قابل دانلود است. خروجی WAV برای محافظت از حافظه به یک ساعت محدود است. صفحه هنگام ضبط باید باز و فعال بماند؛ خروج ناگهانی قبل از پایان ضبط می‌تواند بخش جاری را از بین ببرد. ترجمه واقعی به کلید، سهمیه، شبکه و مدل در دسترس Gemini وابسته است. سازگاری عملی یاندکس و کیوی اندروید با دستگاه واقعی در این محیط بررسی نشده است.

اعتبارسنجی این انتشار: `pnpm test`، `pnpm typecheck`، `pnpm lint` و ساخت استاتیک با پایه `/HamAva`. آزمون‌های مرورگری از پاسخ ساختگی Gemini استفاده می‌کنند؛ آزمون کیفی ترجمه و شباهت صدا با سرویس واقعی محسوب نمی‌شوند.

## تاریخچه: تازه‌های نسخه ۱.۵


**زمان‌بندی درست زیرنویس برای فایل و لینک مستقیم.** تا نسخه ۱.۴ فایل لوکال با «ترجمه زنده» تحلیل می‌شد و چون هر پاس Gemini با تأخیر شبکه می‌رسید، زیرنویس‌ها یک فاصله ثابت جلو یا عقب می‌افتادند. اکنون فایل و لینک مستقیم مثل یوتیوب با تحلیل دسته‌ای ترجمه می‌شوند (`translateMedia` در `lib/hamava/gemini.ts`)؛ مُهر زمانی از خودِ رسانه برمی‌گردد و هر پنجره ۱۵ دقیقه‌ای ناتمام، به‌طور خودکار ادامه پیدا می‌کند. بعد از تحلیل، صدای فایل رمزگشایی و بلوک‌های گفتار واقعی اندازه‌گیری می‌شود (`speechTimeline`) و هر خط روی گفتار واقعی تنظیم می‌شود (`syncCuesToAudio`) تا باقی‌ماندهٔ انحراف مدل هم حذف شود. فایل‌های بزرگ‌تر از سقف ارسال مستقیم (حدود ۱۰ مگابایت) همچنان با ترجمه زنده اجرا می‌شوند و زمان‌بندی‌شان در پایان نشست با همان روش اندازه‌گیری اصلاح می‌شود.

**دانلود خروجی برای همه منابع، از جمله یوتیوب.** مرورگر اجازه ضبط تصویر یوتیوب را نمی‌دهد، اما صدای دوبله آماده‌شده می‌تواند آفلاین ساخته شود: دکمه «دانلود صدای دوبله» همه قطعه‌های صدا را سر جای cue خودشان روی یک خط زمانی می‌چیند (`renderDubbingTrack` و `mixClipsOnTimeline`) و یک فایل WAV تک‌کانالهٔ دقیق می‌سازد که می‌توانید در هر ویرایشگری روی ویدیوی اصلی میکس کنید. برای فایل و لینک مستقیم، ضبط ویدیوی دوبله (WebM) مثل قبل هست و زیرنویس SRT برای همه منابع با نام خود ویدیو دانلود می‌شود.

**بهسازی‌های فنی:** آزمون‌ها از ۱۶ به ۳۰ رسیدند (زمان‌بندی، هماهنگ‌سازی با صدا، میکس و WAV)، `pnpm lint` بدون خطا شد و در CI هم اجرا می‌شود، تنظیمات تک‌منبع شدند (`shared.js` فقط کد صوتی/زنده را نگه می‌دارد)، نوع‌های بی‌دقت `any` حذف شدند و نسخه در `package.json` و هدر برنامه به ۱.۵ به‌روزرسانی شد.

## اصلاح زیرنویس و خروجی در نسخه ۱.۴

پاسخ‌های طولانی Gemini دیگر به‌صورت یک پاراگراف روی کل پلیر نمایش داده نمی‌شوند. هر cue به جمله‌های کوتاه‌تر شکسته، زمان آن متناسب با طول متن در بازه‌ی خودش توزیع و فقط cue فعال روی تصویر نشان داده می‌شود.

در فایل و لینک مستقیم، دکمه‌ی «ساخت خروجی دوبله» ویدیوی اصلی را با ترک تصویر و میکس صدای اصلی/دوبله‌ی Web Audio در قالب WebM ضبط می‌کند. این کار فایل را به سرور ارسال نمی‌کند و در گوشی باید صفحه باز بماند. یوتیوب داخل iframe قابل استخراج و ضبط خام نیست؛ برای آن SRT قابل دریافت است و ساخت MP4 واقعی نیاز به مسیر جداگانه‌ی سرور و FFmpeg دارد.

## اصلاح اتصال در نسخه ۱.۳

علت خطای کلی اتصال در درخواست‌های یوتیوب و TTS، هدر `Api-Revision` بود: سرویس Interactions گوگل این هدر را در پیش‌درخواست CORS مرورگر رد می‌کرد. هدر حذف شده و درخواست فقط `Content-Type` و `x-goog-api-key` دارد. همین تغییر در [SDK رسمی گوگل](https://github.com/googleapis/js-genai/pull/1752) هم انجام شده است.

خطاهای HTTP، کلید نامعتبر، منطقه، مدل، سهمیه، قطع شبکه و زمان انتظار از هم جدا هستند و کد/جزئیات پاسخ گوگل با پوشاندن کلید نمایش داده می‌شود. پاسخ خطای آرایه‌ای گوگل نیز خوانده می‌شود. هر درخواست حداکثر ۳ دقیقه منتظر می‌ماند و درخواست تولید محتوا به‌طور خودکار تکرار نمی‌شود. لغو آماده‌سازی، درخواست مرورگر را متوقف می‌کند؛ گوگل ممکن است پردازش ارسال‌شده را محاسبه کند.

## محدودیت‌های واقعی

- سقف دقیقه یا اشتراک داخلی وجود ندارد؛ هزینه، سهمیه، منطقه و دسترسی به مدل‌ها تابع حساب Gemini است.
- ویدیوی یوتیوب باید عمومی، قابل جاسازی و قابل پردازش توسط Gemini باشد. پخش زنده برای آماده‌سازی پشتیبانی نمی‌شود.
- API فعلی Gemini برای YouTube بازه‌ی `start_offset/end_offset` را در ورودی URL نمی‌پذیرد؛ تلاش برای ارسال آن باعث خطای 400 می‌شود. بنابراین یوتیوب یک‌بار کامل تحلیل می‌شود و قطعه‌سازی فقط برای مسیرهای دارای رسانه‌ی مستقیم قابل اتکا است.
- زمان‌بندی و تشخیص ویژگی صدای گوینده تقریبی است. دوبله آماده یوتیوب از صداهای آماده استفاده می‌کند و صدای اصلی را کلون نمی‌کند.
- ترجمه همزمان تأخیر دارد. رفتن به پس‌زمینه پخش را متوقف می‌کند؛ ترجمه را در صفحه فعال انجام بده.
- اگر ساخت دوبله شکست بخورد، زیرنویس کامل‌شده حفظ می‌شود؛ حالت «زیرنویس» را انتخاب کن یا دوباره ساخت دوبله را بزن.
- اگر مدل ترجمه یوتیوب با خطای موقت 429/5xx شلوغ باشد، برنامه یک‌بار خودکار `gemini-3.5-flash-lite` را امتحان می‌کند؛ درخواست‌ها بی‌نهایت تکرار نمی‌شوند. مدل‌های پیش‌نمایش ممکن است تغییر کنند؛ شناسه مدل‌ها در تنظیمات قابل ویرایش است.

## آزمون و منابع API

آزمون‌ها اعتبارسنجی لینک، تنظیمات و پوشاندن کلید، زمان‌بندی متن، تفکیک گوینده، WAV، ترجمه چندبخشی، انتخاب صدا، لغو، زمان انتظار، خطاهای HTTP، حذف هدر مسدودکننده CORS، پنجره‌بندی تحلیل رسانه، ترمیم خط زمانی، هماهنگ‌سازی cue با صدای اندازه‌گیری‌شده، میکس آفلاین و مسیر `translateMedia` (شامل ادامه خودکار و رد فایل بزرگ) را بررسی می‌کنند. آزمون‌های تولید محتوا پاسخ شبیه‌سازی‌شده دارند؛ کیفیت ترجمه، صدا و صورتحساب بدون کلید واقعی قابل تأیید نیست.

بررسی واقعی شبکه در ۲۰۲۶/۰۹/۱۶: پیش‌درخواست Google با هدر اضافی 403 و بدون آن 200 بود. ارسال کلید آزمایشی نامعتبر بدون هدر اضافی پاسخ خوانای 400 و جزئیات `API_KEY_INVALID` برگرداند.

منابع رسمی:

- [Live Translate](https://ai.google.dev/gemini-api/docs/live-api/live-translate)
- [Video understanding](https://ai.google.dev/gemini-api/docs/video-understanding)
- [Speech generation](https://ai.google.dev/gemini-api/docs/speech-generation)
- [Interactions API](https://ai.google.dev/api/interactions-api)
- [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference)

مدل‌های پیش‌فرض: `gemini-3.5-live-translate-preview`، `gemini-3.8-flash` و `gemini-3.1-flash-tts-preview`.

مجوز فونت همراه در `public/fonts/OFL-Vazir.txt` نگه‌داری شده است.

## انتخاب مدل برای این برنامه

| مدل | کاربرد مناسب |
| --- | --- |
| `gemini-3.5-live-translate-preview` | انتخاب فعلی برای ترجمه پیوسته صدا به فارسی؛ متن ترجمه هم دریافت می‌شود. |
| `gemini-3.8-live` | دستیار مکالمه‌ای صوتی؛ جایگزینی آن در مسیر ترجمه به پیکربندی و منطق متفاوت نیاز دارد. |
| `gemini-3.8-live-extended-thinking` | مکالمه همراه با استدلال پیچیده؛ برای دوبله این برنامه انتخاب پیش‌فرض نیست. |
| `gemini-3.5-transcribe-live` | رونویسی زنده گفتار؛ برای ترجمه فارسی باید مرحله ترجمه متن اضافه شود. |
| `gemini-3.5-transcribe` | رونویسی فایل صوتی با زمان‌بندی واژه و تفکیک گوینده؛ دوبله تولید نمی‌کند. |

این برنامه مسیر آماده‌سازی یوتیوب را با Flash و TTS اجرا می‌کند. صرف تغییر نام یکی از این مدل‌ها، مسیر Transcribe یا Live Agent را پیاده‌سازی نمی‌کند. [فهرست رسمی مدل‌ها](https://ai.google.dev/gemini-api/docs/models) و [راهنمای Transcribe](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-transcribe).

### آزمون مرورگر (گزارش قبلی ۱.۰.۳)

پس از `HAMAVA_BASE_PATH=/HamAva pnpm build:pages`، فایل `tests/browser-smoke.mjs` با Playwright/Chromium و ffmpeg اجرا می‌شود. در صورت نصب Playwright خارج از پروژه، مسیر ماژول را در `PLAYWRIGHT_MODULE` و مسیر مرورگر را در `BROWSER_EXECUTABLE` بده و `node tests/browser-smoke.mjs` را اجرا کن. این آزمون فایل نمونه می‌سازد، API را شبیه‌سازی می‌کند و پخش زیرنویس محلی، SRT/VTT/WAV، ضبط ویدیو بدون درخواست API اضافه، AudioWorklet، خروجی زنده با ولوم صفر، بازیابی آرشیو و عرض صفحه موبایل را بررسی می‌کند.
